01

Overview

Phase 2 put a nightly two-way sync between the point-of-sale and the warehouse system, with a reconciliation report and alerting on failed runs. The sync is running and the weekly by-hand reconciliation is gone. What is left is visibility: the data is correct now, but reading it still means opening two systems and a report attachment.

Phase 3 is the read layer. One place that answers what is in stock right now, which lines disagreed and need a human, and how each location is tracking. No new integrations, no changes to the sync itself.

02

Scope of work

2.1 Live stock view

DeliverableDescription
Current positionOn-hand by SKU across all three locations, sourced from the Phase 2 sync, refreshed on each run.
Search and filterBy SKU, description, location and stock band, so a question about one line takes seconds rather than an export.

2.2 Exception queue

DeliverableDescription
Disagreement listEvery line where the two systems did not reconcile on the last run, oldest first, with both values shown side by side.
Resolve and annotateMark a line resolved with a short note. The note stays on the line so the next person sees why it was closed.
AgeingA line unresolved past a threshold is surfaced at the top. Exceptions that nobody looks at are the failure mode this is built against.

2.3 Per-location drilldown

DeliverableDescription
Location viewThe same stock and exception views scoped to one store, for the people who only run one.
TrendException count and unreconciled value per location over time, so a store that is drifting shows up before it becomes a stock-out.
