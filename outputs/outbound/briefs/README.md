# outputs/outbound/briefs/

One file per prospect, written by `skills/prospect-brief`. Naming: `<company-slug>-YYYY-MM-DD.md`.

A brief is a decision record, not a research dump. It exists so the decision to spend an opener slot
on someone, or not to, is made once, in writing, against the ladder in
`../prospect-gate.md` rather than re-litigated from memory every time the name comes up again.

What a brief holds:

- the moment it was written for (post-accept, pre-send, or inbound) and the verdict in that moment's
  vocabulary, which the gate owns
- the ladder applied layer by layer, with the evidence that moved each one, and what was checked and
  came back empty
- the pain-bank match, cited by entry id from `knowledge/pain-points/pain-point-bank.md`
- opener prep, and nothing sent

Two standing limits, both from `CLAUDE.md`:

- **No send authority.** A brief can conclude SEND and still sit here until Sam says send it. The
  skill drafts, Sam sends.
- **No `knowledge/` write licence.** A brief is an output. If it turns up something durable, a new
  pain point, a corridor that keeps paying off, that gets promoted into `knowledge/` by a separate
  deliberate write, never as a side effect of writing a brief.

This directory is committed. The briefs are cheap to regenerate and are worth keeping, because the
useful signal is the pattern across them: which ladder layers actually predicted a reply, and which
ones everybody kept scoring and nobody ever used.
